Before you begin

Small checklist. Serious tools.

Cross works close to ChromeOS, so it expects a Developer Mode machine and a real VT-2 shell.

01

Developer Mode

ChromeOS Developer Mode must be enabled. Cross does not run inside Crostini.

02

VT-2 access

Run setup and service commands from VT-2 as chronos, never as root.

03

Supported hardware

An x86_64 or aarch64 Chromebook with at least 1.2 GiB free under /usr/local.

Developer Mode reduces device security. Back up your files and read the EULA shown by the installer before accepting it.

Native-feeling tools, isolated userland.

Cross combines Alpine's signed packages with a localhost-only SSH boundary. You work from crosh; a VT-2 service owns the privileged setup.

Signed packages only

System tools and libraries come from Alpine's main and community repositories.

No VM tax

The Alpine userland runs in a chroot with ChromeOS devices, proc, sys, DNS, and HOME mounted in.

Localhost by design

OpenSSH listens only on IPv4 loopback and accepts a generated Ed25519 key—no passwords or forwarding.

Files & projects

Your files don't move.

ChromeOS HOME is bind-mounted at the identical path inside Alpine, so tools, editors, and shells agree on where your project lives.

ChromeOS/home/chronos/user/MyFiles/code/app
same files
Cross / Alpine/home/chronos/user/MyFiles/code/app

Cross remounts only the Alpine-facing HOME bind with exec,nosuid,nodev. That lets Cargo output, npm helpers, and HOME-resident ELF binaries execute without moving build caches into special directories.

An alternate work area remains available at $CROSS_WORK/chronos for projects you prefer to keep under the Cross prefix.

One shell, two ways to work.

Best for a focused development session. Type exit to return to crosh.

Prefix a command with cross to execute it in Alpine without opening an interactive shell.

Use Alpine's package manager

Search, install, and upgrade signed Alpine packages with apk.

sudo apk add python3

From VT-2

Keep the bridge healthy.

Service commands need VT-2 because they manage mounts and the Alpine SSH daemon.

CommandWhat it does
cross-service statusShow whether the localhost service is running.
cross-service startPrepare mounts, sync DNS, and start authenticated SSH.
cross-service stopStop chroot processes and unmount runtime paths.
cross-service restartCleanly stop and start the service.
cross-service doctorInspect mounts, keys, SSH settings, and authentication.
cross-service log 120Show the most recent service log lines.
On stock verified ChromeOS, /etc/init is usually read-only. Cross starts immediately after setup, but you may need cross-service start from VT-2 after a reboot.

Alpine packages

Use apk upgrade

Refresh installed compilers, runtimes, libraries, and utilities from the configured Alpine repositories.

Know the trade-offs

Powerful because it is privileged.

Cross is intentionally transparent about where ChromeOS protections are relaxed.

✓ Constrained by design

  • SSH binds only to 127.0.0.1
  • Key authentication only; no passwords
  • No forwarding, tunneling, or root login
  • nosuid,nodev retained on HOME bind
  • Official Alpine packages and checksums

! Protections you relax

  • Developer Mode weakens verified-boot guarantees
  • The Alpine-facing HOME bind permits execution
  • Alpine chronos has passwordless sudo
  • A symlink-policy exception may last until reboot
  • No mount namespace isolates the executable alias

Treat Cross like a local development system with root access. Review scripts, install trusted packages, and keep backups of anything important.

Troubleshooting

Start with the doctor.

VT-2 diagnostic cross-service doctor

Open VT-2 and start the service with /usr/local/cross/bin/cross-service start. This is commonly needed after reboot when ChromeOS cannot install the optional Upstart job.

Run cross-service doctor from VT-2 to inspect key ownership, modes, and the authentication probe. Rerun cross.sh to repair generated keys and configuration.

Restart the service to resync ChromeOS DNS into Alpine. Then test with cross getent ahosts dl-cdn.alpinelinux.org.

Reload the shell profile with source ~/.bashrc. For the first update from an old release, explicitly use /usr/bin/curl and /bin/bash.

FAQ

Good questions, short answers.

Is Cross a VM?

No. Alpine runs in a chroot on the ChromeOS kernel. There is no virtual machine or container runtime.

Is Cross Chromebrew?

No. Cross calls itself a successor project, but uses Alpine's apk ecosystem rather than Chromebrew packages.

Can I use Crostini instead?

Yes—Crostini is the safer, officially supported choice for most users. Cross is for Developer Mode workflows that need direct host-adjacent tooling.

Does it change my HOME mount?

The original ChromeOS HOME mount flags remain unchanged. Cross remounts its bind-mount view with execution enabled.

Where is Cross installed?

The default prefix is /usr/local/cross, including the Alpine rootfs, configuration, cache, logs, and wrappers.

What license does Cross use?

Cross is released under CC0. Alpine and all third-party packages keep their own licenses.
